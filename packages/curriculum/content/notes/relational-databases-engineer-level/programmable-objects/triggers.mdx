<Hook>Triggers make a statement do more than it says. That hidden work is useful—and exactly why a test must observe timing, scope, ordering, and side effects instead of trusting the visible SQL.</Hook>

<Callout type="analogy">A <Term define="Database code fired automatically for a declared event, timing, and scope.">trigger</Term> is a mousetrap: a defined event releases a mechanism. Test what sets it off, what it changes, whether it fires once or per row, and whether resetting it causes another snap.</Callout>

## Map event to effect

A PostgreSQL trigger function takes no ordinary arguments and returns `trigger`. Its context includes `NEW`, `OLD`, `TG_OP`, and `TG_LEVEL`. A `BEFORE` row trigger may replace `NEW` or return null to skip the row; an `AFTER` trigger observes the final effect, and its return value is ignored.

<Callout type="tip">Query `pg_trigger` and use `pg_get_triggerdef(oid)` before testing. The active definition—not a migration file you remember—is the executable truth.</Callout>

<Callout type="mistake">Testing a one-row UPDATE when production statements update thousands. A row trigger fires per row; a statement trigger fires once. Your fixture must distinguish the two.</Callout>

<CodePlayground language="python" title="Count row-level trigger effects" code={`rows = [{"id": 1}, {"id": 2}, {"id": 3}]
audit = []
for row in rows:
    row["status"] = "READY"          # BEFORE-row effect
    audit.append(("UPDATE", row["id"]))  # AFTER-row effect

assert len(audit) == len(rows)
print(rows)
print("audit events:", audit)`}/>

<CodePlayground language="java" title="Simulate trigger timing in Java" code={`import java.util.*;
class Main {
  static Map<String, String> beforeInsert(Map<String, String> row) {
    Map<String, String> copy = new HashMap<>(row);
    copy.put("status", copy.getOrDefault("status", "PENDING").toUpperCase());
    return copy;
  }
  public static void main(String[] args) {
    List<String> audit = new ArrayList<>();
    Map<String, String> stored = beforeInsert(Map.of("id", "42", "status", "pending"));
    audit.add("INSERT id=" + stored.get("id") + " status=" + stored.get("status"));
    System.out.println(stored);
    System.out.println(audit);
  }
}`}/>

<WorkedExample title="An updated_at trigger under a no-op update">Arrange one row with a known timestamp. Update a business field and assert `updated_at` advances. Run a no-op assignment and decide from the contract whether it should advance. Update three rows in one statement and assert exactly three timestamps—not one, not six.</WorkedExample>
