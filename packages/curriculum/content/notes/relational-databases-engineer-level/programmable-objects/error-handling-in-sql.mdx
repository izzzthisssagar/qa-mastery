<Hook>Error text is written for humans and may change; an error contract needs machine-stable evidence. In PostgreSQL that starts with SQLSTATE, then constraint and object diagnostics, then the state left behind.</Hook>

<Callout type="analogy">An error handler is a fire alarm system. The code identifies the class of incident, diagnostics locate it, rollback contains it, and logs help responders. Painting over the alarm message fixes nothing.</Callout>

## Assert the failure contract

PostgreSQL assigns five-character <Term define="A machine-readable five-character code that classifies a database outcome or error.">SQLSTATE</Term> codes. The first two characters identify a class, such as `23` for integrity constraint violations. In PL/pgSQL, an `EXCEPTION` block can catch by condition name or SQLSTATE, and `GET STACKED DIAGNOSTICS` can retrieve fields such as constraint name and message detail.

<Callout type="tip">Assert SQLSTATE and, when relevant, `CONSTRAINT_NAME`. Do not parse localized message text to decide application behavior.</Callout>

<Callout type="mistake">Catching `OTHERS` and returning success. It destroys the original signal and can make callers trust a partially completed business operation.</Callout>

    if code == "23505":
        return "reject duplicate"
    if code == "40001":
        return "retry whole transaction"
    if code.startswith("23"):

<CodePlayground language="java" title="Route errors by SQLSTATE in Java" code={`import java.util.*;
class Main {
  static String decision(String sqlState) {
    if (sqlState.equals("23505")) return "reject duplicate";
    if (sqlState.equals("40001")) return "retry whole transaction";
    if (sqlState.startsWith("23")) return "reject integrity violation";
    return "rethrow and investigate";
  }
  public static void main(String[] args) {
    for (String code : List.of("23505", "23503", "40001", "XX000"))
      System.out.println(code + " -> " + decision(code));
  }
}`}/>
