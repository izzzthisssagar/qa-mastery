**Boundary value analysis (BVA)** targets the *edges* of input ranges, because
off-by-one errors (`<` vs `<=`, `>` vs `>=`) live there. It's the natural partner
of [equivalence partitioning](/notes/foundations/test-design/equivalence-partitioning):
EP tells you the ranges, BVA tells you which points in them to test.

## The values to test

For a range with a lower bound **L** and upper bound **U**, test:

- **L − 1** (just below), **L** (the min), **L + 1** (just inside)
- **U − 1** (just inside), **U** (the max), **U + 1** (just above)

## Example

A field accepts **1–100**. The boundary values are:

| Value | Class | Expected |
|-------|-------|----------|
| `0` | below | rejected |
| `1` | min | accepted |
| `2` | inside | accepted |
| `99` | inside | accepted |
| `100` | max | accepted |
| `101` | above | rejected |

## Two-value vs three-value

The **two-value** form tests each boundary and the point on its other side (`0,1`
and `100,101`). The stricter **three-value** form adds the point just inside each
edge (`0,1,2` and `99,100,101`) — more thorough, catching defects that only
appear one step in. Use three-value where the risk warrants it.
