title: Equivalence partitioning
summary: Group inputs that the system treats the same, then test one representative from each group — fewer tests, same coverage.

---

**Equivalence partitioning (EP)** divides an input domain into *classes* the
system is expected to handle identically. If one value in a class reveals a
defect, the others probably would too — so you test **one representative per
class** instead of every value.

## Example

A field accepts an age between **18 and 65**. The partitions are:

| Partition | Example | Expected |
|-----------|---------|----------|
| Below range (`< 18`) | `10` | rejected |
| Valid range (`18–65`) | `40` | accepted |
| Above range (`> 65`) | `80` | rejected |

Three tests cover the meaningful behaviour of an input that has millions of
possible values.

## Valid vs invalid classes

Partition both the **valid** inputs (should be accepted) and the **invalid**
ones (should be rejected). Invalid classes catch missing validation — a common
source of security and data-integrity bugs.

## Pairs with boundary value analysis

EP tells you *which ranges* to test; [boundary value analysis](/notes/foundations/test-design/boundary-value-analysis)
tells you *which points within them* are riskiest (the edges). Use the two
together.
